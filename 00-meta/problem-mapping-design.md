# Problem → Knowledge Mapping 设计

> 版本：v0.5.0（冻结）  
> 范围：问题原型、知识调用栈、证据门槛、工作流与升级边界

问题层不是“答案库”，而是一组把开放现实问题翻译为知识图谱查询的可复用原型。它回答：面对某类问题，先澄清什么，调用哪些领域、骨架和模型，需要什么证据，何时必须停止自行判断并升级给专业人员。

## 1. 从提问到调用栈

```text
现实情境
  → 问题原型（目标、成功标准、受影响者、尺度、时间、价值）
  → 知识调用栈（H2 + 核心骨架 + Thinking + Universal）
  → 证据计划（测量、比较、机制、反证、来源质量）
  → 工作流（框定 → 建模 → 取证 → 比较 → 行动/更新）
  → 输出物与升级判断
```

问题原型不按传统学科分类。一个模板可以调用多个 H2，但每个引用都必须落实到领域骨架或模型；不能只写“需要经济学、心理学、历史学”而不说明调用什么结构。

## 2. 六个问题家族

| 家族 | 核心任务 | 典型原型 |
|---|---|---|
| `sensemaking` | 描述、测量、解释和诊断 | 状态测量、因果诊断、历史文化解释 |
| `prediction-decision` | 预测、选择、配置和估值 | 早期预警、不确定决策、资源配置、投资判断 |
| `design-intervention` | 设计、建造、评估和改变 | 系统设计、项目评估、新技术、行为学习、创造 |
| `coordination-governance` | 处理多主体、制度、政策与冲突 | 治理监管、谈判协调、组织变革、社会政策 |
| `risk-response` | 识别危害、控制风险、响应和恢复 | 安全危机、医疗健康、可持续转型 |
| `learning-meaning` | 发展能力、规划生活、解释意义 | 学习路线、个人决策、历史文化解释、创造 |

家族允许重叠；它是检索面，不是排他父级。主身份仍是稳定的 `hkm:problem-template:*` 节点。

## 3. 最小字段

每个问题原型必须包含：

- `primary_aim` 与 `secondary_aims`：说明它主要要产生哪类认识或行动；
- `trigger_questions` 与 `success_criteria`：区分问题入口和可验收结果；
- `scoping_dimensions`：对象、主体、时间尺度、系统尺度、价值与约束；
- `knowledge_calls`：H2、核心骨架、Thinking Models、Universal Models 四层调用；
- `evidence_requirements`：结论成立前必须取得的证据，而非装饰性数据；
- `workflow`：每步都写动作、产物和检查门；
- `outputs`：模板应产出的可复查工件；
- `failure_modes`、`escalation_conditions` 与 `boundary_notes`：说明哪里会误导、何时升级、哪些结论不能推出。

## 4. 映射原则

1. **从目标开始**：同一主题的解释、预测、评价和设计需要不同证据与模型。
2. **先边界后数据**：不先说明对象、主体、尺度和时间窗，更多数据只会精确回答错误问题。
3. **调用骨架而非学科名**：每个领域调用至少由一个同域核心节点支持。
4. **模型成组使用**：至少组合概率/证据、机制/系统、决策/边界三类思维；单一模型不能成为万能钥匙。
5. **保留竞争解释**：工作流必须包含反证、敏感性或替代解释检查。
6. **输出可复查**：结论同时记录假设、证据、置信度、未决项、监测指标和更新条件。
7. **风险决定升级**：医学、法律、安全、金融和不可逆公共决策需要更严格证据与专业责任链。

## 5. 冻结门槛

阶段 5 已达到冻结条件：20 个问题原型覆盖主要认识与行动目标、全部 20 个 H2、41 个 Thinking Models 和 22 个 Universal Models，并完整呈现投资、新技术和社会政策三个压力测试。校验器会拒绝未知调用、领域—骨架错配、过短工作流、缺失证据门槛和空升级条件。后续新增模板必须证明它代表新的问题结构，而不只是换了主题名词。
