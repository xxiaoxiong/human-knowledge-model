# 分类原则

## 1. 分类服务于任务

不存在脱离目的的唯一正确分类。HKM 的首要用户是希望建立宏观认识、跨学科学习并解决现实问题的个人，因此优先：

```text
认知可导航性 + 解释力 + 迁移性 + 问题调用能力 + 可持续扩展性
```

它不以排书、统计学位、统计产业或复刻大学组织结构为首要目标。外部分类是覆盖检查与映射来源，不是主结构。

## 2. 先分清“什么东西”，再决定“放在哪里”

新增节点依次回答：

1. 它指向现实对象，还是人类对现实的表征？
2. 它是范围、概念、主张、理论、模型、方法、工具、技能、规范、案例还是问题？
3. 它的核心问题和主要对象是什么？
4. 哪个领域是最稳定的主导航入口？
5. 它还与哪些领域、方法、问题和模型相连？

类型判错比父目录判错更严重。例如把“系统思维”建成社会科学的一个子学科，会丢失其跨物理、生物、工程、计算和组织的迁移价值。

## 3. 领域成立的六项测试

候选 H2 一级领域需要满足大部分条件：

| 测试 | 问题 |
|---|---|
| 核心问题 | 是否有跨时代持续存在、不可由邻域完全替代的问题？ |
| 对象凝聚 | 研究对象或实践对象是否有相对统一性？ |
| 认识传统 | 是否形成可识别的证据、方法或论证传统？ |
| 结构骨架 | 是否能提炼 10–30 个高解释力节点，而非杂项集合？ |
| 迁移/实践价值 | 单列是否显著改善学习、推理或行动？ |
| 边界可说明 | 能否说明核心、共享边缘、桥接区与不包含内容？ |

只满足制度存在性（“大学里有这个系”）不足以单列；只因为热门或产业规模大也不足以单列。

## 4. 主归属规则

节点可能属于多个领域，但为导航设置一个 `primary-domain`。依次使用：

1. **核心问题优先**：它主要回答哪类问题？
2. **解释机制优先于应用场景**：通用原理归原理领域，具体使用以 `applies-to` 连接；
3. **稳定身份优先于当前组织**：不随院系、行业或流行名称频繁移动；
4. **生成传统作为平局规则**：核心概念最初由哪个研究传统形成并持续维护？
5. **用户可发现性复核**：主归属是否让目标用户最容易找到？

主归属只解决入口，不表示所有权。次级领域使用 `in-domain`；跨学科稳定共同体可建独立 subdomain，并同时连接多个 H2 领域。

## 5. 抽象层级规则

### 5.1 层级只表示范围包含

`H2 → H3 → H4` 必须能读成“较窄知识范围属于较广知识范围”。以下序列是错误的：

```text
经济学 → 供给需求模型 → 回归分析 → Excel → 股票投资
```

它混合了领域、模型、方法、工具和应用。正确做法是保留各自类型并连边：

```text
供给需求模型  primary-domain  经济学
回归分析      applies-to       经济问题
Excel         implements       表格计算方法
估值实践      uses             会计数据 / 概率模型 / 行业知识
```

### 5.2 “is-a”替换测试

若 `A is-a B`，任何 A 必须也是 B。若不满足，检查是否应为：

- `part-of`：轮胎不是汽车的一种；
- `instance-of`：某公司不是公司概念的子类；
- `applies-to`：统计学不是医学的一部分；
- `derived-from`：热力学结论不必是统计力学的一类；
- `analogous-to`：相似结构不等于同一类别。

### 5.3 普遍模型上提

如果一个模型在至少三个差异明显的领域中保持相同核心机制，并能明确写出结构映射与失效条件，则将其候选为 `Universal Model`；领域文件只保留实例与链接，不复制完整定义。

## 6. 认识方式不可被学科吞并

经验、形式、解释、诠释、规范、设计和具身实践都是合法知识形态：

| 认识方式 | 主要质量问题 |
|---|---|
| 经验 | 观测可靠吗？样本与测量有效吗？ |
| 形式 | 前提明确吗？推导有效吗？ |
| 因果解释 | 机制与替代解释被区分了吗？ |
| 历史/诠释 | 语境、来源与解释者位置被说明了吗？ |
| 规范 | 价值前提、一致性与权衡是否显式？ |
| 设计 | 是否在真实约束下有效、可用、安全？ |
| 具身实践 | 能否稳定表现？如何训练与传承？ |

不能用单一标准抹平差异，也不能因标准不同而放弃质量判断。

## 7. 覆盖原则

一级地图使用多套外部分类进行“遗漏压力测试”：

- 学术/R&D：是否覆盖基本研究领域？
- 教育：是否覆盖主要学习与职业训练领域？
- 图书分类：普通人可能查找的重要主题是否有入口？
- 产业活动：生产、服务、基础设施与组织实践是否被遗漏？
- 职业/技能：程序性、手工、照护、管理和服务知识是否被遗漏？
- 现实问题：健康、食物、环境、治理、安全、沟通、生活是否可路由？

覆盖不意味着每个外部大类都成为 H2。它可能被表示为领域、应用分面、实践节点或多个领域的组合视图。

## 8. 合并、拆分与桥接规则

### 合并

当两个领域长期共享核心问题、对象、方法和骨架，而且分开只反映院系历史时，应合并或降为 H3。

### 拆分

当一个范围包含多个互不依赖的核心问题、学习路线过长、内部关系稀疏，或对问题调用造成持续混淆时，应拆分。

### 建桥

当范围由多个领域共同支撑但已形成稳定问题和方法组合时，建立桥接 subdomain，而不是复制节点。例如：

```text
认知科学 = 心智与行为 + 计算与 AI + 语言 + 生命科学 + 哲学
气候科学 = 地球环境 + 物理 + 生命 + 计算建模
公共卫生 = 健康医学 + 社会 + 经济 + 治理 + 统计
```

## 9. 知识边界与认识状态

每个结构性节点至少说明：

- 定义和核心问题；
- 前提与适用尺度；
- 能解释/解决什么；
- 不能解释/解决什么；
- 证据或论证类型；
- 争议与替代模型；
- 现实应用与潜在误用。

严禁把争议性主张仅以中性名词包装成共识。历史模型可以收录，但标记适用史、认识状态和替代关系。

## 10. 学习优先级原则

S/A/B/C/D 是学习价值，不是知识真伪或社会地位。评分维度：

```text
迁移范围、使用频率、解释力、决策价值、前置杠杆、风险防护、学习成本
```

优先级应面向学习者画像和目标。默认个人通识视图可给一个基线，但专业路线会重排。高专业度知识可能对某职业为 S，对普通通识为 C/D。

## 11. 文件与重复控制

1. 一个规范节点只有一个稳定 ID；
2. 领域文档只展开本领域语境，不复制通用模型全文；
3. 关系写入数据源，Markdown 图是派生解释；
4. 同义词不是新节点，歧义词必须拆义；
5. 相同文本不等于相同概念，相同概念也不要求相同文本；
6. 每次新增 H2/H3 节点必须检查父层、边界、桥接和至少一个现实问题入口。

## 12. 结构审计清单

### 节点

- 是否把对象、知识、方法、工具和问题混在同一层？
- 是否存在只因名称不同而重复的节点？
- 是否有“其他/杂项”长期吸收大量内容？
- 是否缺少定义、边界或核心问题？

### 关系

- 是否大量使用无语义的 `related`？
- `is-a`、`part-of`、`depends-on` 是否误用？
- 强因果、证据或矛盾关系是否缺少语境和来源？
- 跨领域桥接是否只是文字提及而没有边？

### 覆盖

- 是否只覆盖学术知识，遗漏实践技能和日常生活？
- 是否只覆盖描述性知识，遗漏规范、设计和行动？
- 是否有重要现实问题无法映射到任何领域组合？

### 学习与使用

- 是否能从问题反查知识？
- 是否能从节点追溯前置知识和证据？
- 是否能解释模型何时失效？
- 删除该节点是否真的破坏结构，还是它只是装饰性罗列？
