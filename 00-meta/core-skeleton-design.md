# 领域核心骨架设计

## 1. 目的

领域骨架不是课程目录、术语频率表或名人理论清单，而是一组能够让学习者和问题求解器重建该领域主要推理链的结构节点。每个 H2 目标为 10–30 个节点：足够支撑定位、解释和迁移，又小到可以整体掌握。

一个合格骨架应同时覆盖：

```text
基本区分与对象
→ 关键机制或规律
→ 表征与模型
→ 证据、测量与方法
→ 决策、设计或实践
→ 边界、失效与价值约束
```

不是每个领域都按同一比例分配。例如历史和宗教更依赖来源、诠释与情境，工程和医学更依赖设计、验证、风险与实践。统一的是字段和质量门槛，不是认识方式。

## 2. 节点准入

候选节点至少满足三项：

1. **结构承重**：删除后会切断多条解释、方法或行动路径；
2. **跨主题复用**：能组织多个 H3，而非只对应一个狭窄事实；
3. **问题价值**：能直接改善描述、解释、预测、诊断、评价、设计或决策；
4. **学习迁移**：掌握后能显著降低后续多个节点的学习成本；
5. **边界教育**：能揭示一种常见误用、尺度错配或证据限制。

仅因著名、历史悠久或容易考试而出现的条目不自动进入骨架。专有理论只有在承担结构功能时进入；其余留到 H4 或详细内容层。

## 3. 数据字段

| 字段 | 含义 |
|---|---|
| `primary_type` / `additional_types` | 概念、原则、模型、框架、方法、技能等本体身份 |
| `primary_domain` | 唯一 H2 主导航；生成 `primary-domain` 边 |
| `related_subdomains` | 直接适用的 H3；生成 `in-scope` 边 |
| `roles` | 在骨架中的功能，不是新本体类型 |
| `aims` / `epistemic_modes` | 解决何种任务、依赖何种认识方式 |
| `learning_priority` | S/A/B/C/D；表示一般学习价值而非真理等级 |
| `prerequisites` | 学习前置；生成前置 → 当前的 `prerequisite-of` 边 |
| `connections` | 其他有方向、有语义、有适用范围的核心关系 |
| `boundary_notes` | 失效条件、相邻类型或不应推出的结论 |

`code`（如 `K03.01`）只用于版本内展示排序；稳定身份是 ID。一个节点若跨域复用，只保留一个 ID，通过多个 `in-scope` 或桥接视图连接，不在各领域复制。

## 4. 四类模板与首轮扩展

| 模板 | 首个领域 | 骨架强调 |
|---|---|---|
| 自然规律 | D03 物质、能量与宇宙 | 测量、守恒、尺度、机制、模型与实验约束 |
| 社会制度 | D10 经济、金融与组织 | 激励、信息、制度、因果识别、分配与协调 |
| 设计工程 | D13 工程、技术与设计 | 需求、约束、生命周期、验证、可靠性与责任 |
| 生活实践 | D20 日常生活与实践 | 可练习能力、检查表、风险阈值、维护和专业求助 |

四个模板通过校验后，首轮扩展选择 D01 元知识、D02 数学、D05 生命与 D06 心智，第二轮加入 D04 地球环境、D07 社会群体、D08 历史文明与 D09 政治法律，第三轮加入 D11 语言传播、D12 计算 AI、D14 健康医学与 D15 农业食品，第四轮完成 D16 教育、D17 安全、D18 艺术与 D19 宗教。这样同时检验规范、形式、经验、历史、解释、符号、计算、高风险临床、制度、生产、审美、意义和实践知识是否能使用同一字段而不被压成同一种推理形态。全部 20 个领域均满足 10–30 节点、H3 全覆盖、前置无环和优先级梯度门槛；冻结证据与主归属审计见 [阶段 3 冻结审计](phase-3-progress-audit.md)。

## 5. 校验门槛

- 每个已发布骨架含 10–30 个节点；
- 每个节点有唯一 ID、代码和一个主领域；
- `related_subdomains` 必须属于该主领域，跨域适用另用关系表达；
- 类型、目的、认识方式、角色和学习优先级必须来自枚举；
- 前置和显式连接的目标必须存在，关系类型必须合法；
- 除基础起点外，节点应至少有一个知识性前置或核心连接；
- S/A 优先级不能覆盖全部节点，避免把“核心”误解为同等学习深度；
- 生成视图和关系必须与数据源一致。
